# RIP 与 OSPF 路由算法

打开本目录的 `index.html`，或从总展厅的“计算机网络”进入。无需安装或构建。

四个场景：

1. RIP：从直连网络开始，邻居通告、距离加一、路由收敛、按下一跳转发。
2. RIP 坏消息传得慢：链路故障、旧通告先到、两节点环路、距离递增到 16；可开启毒性逆转，对照同一次故障。
3. OSPF：跟踪一份 LSA 的泛洪，收齐各路由器的通告后拼图，逐轮演示 Dijkstra，比较总开销与跳数。
4. OSPF 故障恢复：C—D 断开，泛洪更新后重新算路，A 到 E 从开销 6 的路线切换到开销 10 的备选路线。

播放、暂停、回退、单步、倍速、进度拖动、关键节点跳转均可用。空格播放/暂停，左右方向键切换步骤（在输入控件内操作时保留原生行为）。系统开启“减少动态效果”时，保留步骤与状态变化，省略移动动画。

## 教学边界

- RIP 每段代价为 1，直连目的网络度量为 1；16 表示不可达，有效距离最多为 15。
- 坏消息场景有意关闭水平分割与毒性逆转，并安排旧消息先到，展示一种可能的异步时序，不是声称所有 RIP 故障都会这样收敛。计数单位是通告步骤，不是真实秒数。
- 毒性逆转阻止本例的两节点环路，不保证消除所有多节点环路。路由毒化与毒性逆转的方向不同。
- OSPF 采用单区域、对称点到点链路，省略重复 LSA、确认/重传、DR/BDR 等细节。LSA 泛洪与 Dijkstra 计算分开；标记“候选”的移动表示本地运算，不是路由报文。
- GSAP 可用时使用其缓动函数；无法联网时自动采用本地缓动，教学功能仍可使用。

## 验证

`node model.test.cjs` 验证 RIP 通告处理、变坏更新、16 的上限、环路计数、毒性逆转、Dijkstra 结果、故障改路与不可达节点。
