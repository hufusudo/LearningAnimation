ARP 在哪里发生？

在以太网里，主机发帧前需要下一跳的 MAC。访问异网的 DNS 或网站时，通常下一跳是默认网关；ARP 缓存命中就无需广播，未命中则先解析。它是发包路径里的条件步骤，不能固定说成“与 DNS 总是并行”。

主机ARP：网关 IP → 网关 MAC默认网关

IP 目的地址仍是远端 DNS / 网站；本地帧的目的 MAC 是下一跳。Wi-Fi、IPv6 等场景的细节另有差异。

有缓存，还会走完整流程吗？
DNS 缓存命中直接得到地址，省去本次外部 DNS 查询。
已有可复用连接可省去新的 TCP / TLS 握手。
HTTP 新鲜缓存命中可直接使用缓存资源；过期资源可能需要条件请求验证。

这些是不同层面的缓存，不是一个统一的“浏览器缓存”。

HTTP/2 和 HTTP/3 有什么不同？
本片 HTTP/1.1一条持久连接，依次请求；实际可开多条连接并行下载。
HTTP/2可以在同一连接中多路复用多个请求与响应流。
HTTP/3使用 QUIC（基于 UDP），不走本片的 TCP 三次握手。
