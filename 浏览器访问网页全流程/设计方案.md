# 浏览器访问网页全流程 · 重设计方案

2026-10-05，用户确认六段主线后实施。本方案取代原“四层泳道、十秒全片”方案。

## 目标与范围

面向已学过 DNS、TCP、HTTP 的学习者，串起一次访问的因果关系。每个动作都能回答：为什么做、谁向谁发送什么、获得什么、接下来为什么能继续。只修改当前模块，不改变全站架构，不新增运行依赖。

## 场景与准确性

采用明确的教学场景：首次访问，DNS / HTTP 缓存未命中，无现成连接；HTTPS、HTTP/1.1、TLS 1.3；同源资源，复用一条持久连接依次获取 CSS、图片和 defer 脚本。域名 learn.example 和 IP 203.0.113.20 均为示意，不发真实网络请求。

DNS 图中只演示客户端与递归解析器的一次查询和应答；DNS 递归细节折叠展示。TLS 以三个消息组概括，明确省略分片、记录、可选消息及协议参数；HTTP 面板显示浏览器解密后的应用层内容，传输中受 TLS 保护。ARP 是本地下一跳寻址，按需要在发帧前进行，不能宣称与 DNS 总是并行。渲染演示中发现资源后可继续解析，实际下载、解析、渲染可以交叠，首屏不要求所有资源已下载。示例选择首次绘制先于 defer 脚本更新的可观察顺序；defer 并不保证先绘制后执行。

## 布局与视觉

延续工程纸张底色 #FAF9F5、白色 #FFFFFF、边框 #E5E4DC；请求钴蓝 #2563EB、响应翡翠 #059669、待完成琥珀 #D97706。字体使用系统中文无衬线，报文与地址用等宽字体。左对齐，正文 14–16px，主标题 26px。

顶部六段可跳转进度 → 地址栏 → 固定的浏览器 / DNS / 网站参与者 → 当前阶段动作舞台。舞台下常驻已得到的目标地址、TCP、TLS、HTML 状态。右侧只展示当前一步的原因、结果和下一步，细节可展开。舞台上方的播放器在滚动时保持可见，负责逐步前进/后退、暂停/续播、当前动作重播、复位和调速。

URL 以分段归属图展示；DNS/TCP/TLS 用时序箭头，向下表示顺序，横向表示通信方向。HTTP 用请求与响应正文。渲染用 HTML、资源清单、DOM + CSSOM → 样式 → 布局 → 绘制，以及从空白、无样式到完整的网页预览。主动画每次只强调一个动作，不混入浏览器多进程实现细节。

## 六段与动作

1. 网址：输入 URL；提取协议、主机名、路径与查询（片段留在本地）。
2. DNS：询问递归解析器；接收地址并保留 IP。
3. TCP：SYN；SYN+ACK；ACK。分别保留双方连接状态及 seq/ack。
4. TLS：ClientHello；服务端消息组（ServerHello、证书、证明、Finished）；客户端验证及 Finished。
5. HTTP：发送含查询参数的 GET / Host；收到 200 OK 与 HTML。
6. 渲染：解析 HTML 发现引用；依次请求并接收 CSS、图片、defer JS；计算样式；布局；绘制；执行示例 defer 脚本，更新页面。

## 动作时序

每次切换先杀死当前时间线，旧动作 150ms 淡出；新视图落位，当前箭头 约 900ms 按发送方向展开；接收结果与状态 350ms 渐显。自动播放在结果出现后停留约 2.5–3 秒再继续，视觉时长不代表真实网络延迟。单步完成后停止。速率以 timeScale 动态调整，不重建当前动作。减少动态效果模式缩短移动但保留阅读停顿。

步骤数据和累积状态是唯一语义来源。跳转、回退、复位通过快照重建，不能保留未来步骤的状态。暂停冻结当前时间线；反复操作不会产生多个调度器。CDN 失败时仍可用单步与跳转看静态图解。

## 验收

六段正确因果；DNS 不返回网页；TCP 完成后才 TLS，TLS 完成后才 HTTP；GET 含 query、不含 fragment；HTTP/1.1 不误演示单连接多路复用；资源发现与渲染可区分。实测单步、回退、跳转、重播、暂停、切速率、复位及连续快速操作。桌面与 375px 手机无横向溢出；键盘可操作；减少动态效果与 CDN 失败可用。执行 npm run check。
