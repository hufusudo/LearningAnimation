系统调用陷入 (trap)
用户程序执行 open/read 时通过软中断把控制权交给内核，参数经寄存器传入。
进程打开文件表
每个进程 PCB 里的一张指针数组，下标就是 fd；0/1/2 通常已被标准流占用。

内核全局的 struct file 数组，保存 offset、打开模式与引用计数，是“共享”的关键。

四条结论，直接背

fd

fd 是整数下标，不是地址。

进程表里存的是指向系统表项的指针；换进程后 fd 可以不同，只要指向同一个 file 就共享状态。

offset

读写位置挂在 file 上，不挂在进程或 inode 上。

dup / fork 出的两个 fd 共享同一 file，因此共享 offset：一边读走 100 字节，另一边接着从 100 开始。

inode

inode 全系统只有一份内存副本。

多个进程各自 open 会各占一个 file 表项（count=1），却共用同一个活动 inode（i_count 累加）。

read

read 不再查目录，三级表直达盘块。

路径解析只在 open 时做一次；之后 read 顺着 fds → file → inode.addrs 直接定位 Block 12。

教学简化：单进程、只读顺序访问，忽略页缓存（buffer cache）、预读与目录项 dentry 缓存；盘块与文件大小为示意值（1240 B，块索引 12/13）。真实内核中 read 还可能直接命中页缓存而不产生磁盘 I/O。
