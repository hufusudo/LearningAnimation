# 动画卡顿修复记录

## 定位

原版在主 Canvas 上逐帧、逐节点设置 `filter = blur(2px)`，同时重新生成球面渐变和阴影。暂停/静止也持续重绘整屏，控件的 `backdrop-filter` 额外模糊动画背景。

使用同一浏览器、1280×720 视口、模拟 DPR=2 的五秒连续「冲突→预备→旋转→变色→复原」场景，丢弃开头 500ms 后采样。只禁用主 Canvas 实时模糊即可明显改善帧间隔，确认其为主要瓶颈。

| 测量项 | 原版 | 仅禁用实时模糊的原版 | 优化版 |
| --- | ---: | ---: | ---: |
| Canvas 实际像素 | 2560×1440 | 2560×1440 | 1920×1080 |
| JavaScript 单帧提交均值 | 0.500ms | 0.327ms | 0.213ms |
| requestAnimationFrame 间隔均值 | 12.154ms | 6.069ms | 6.061ms |
| 帧间隔 P95 | 24.2ms | 6.1ms | 6.1ms |
| 最大帧间隔 | 60.6ms | 12.2ms | 6.2ms |
| 有效样本数 | 373 | 742 | 743 |

这些数据记录本次本机浏览器测试，不保证其他设备取得相同帧率。JavaScript 提交时间不等于 GPU 渲染耗时。

## 修复

- 将红/黑光球、柔化版本和冷/暖光点预绘为 6 张可复用的小图；模糊与阴影只在缓存创建时计算，主 Canvas 每帧贴图。
- 变色叠合缓存材质，保留光晕、双红电弧、旋转、流光、双黑环；数值文字直接绘制，保持可读。
- 主 Canvas 使用不透明上下文，缓存背景渐变；避免重复清屏、重复初始化边集合与根至 NIL 路径。
- 随动提示改为 `translate3d` 移动，只在位置变化时写入样式；控件采用静态半透明底色。
- DPR 最高 1.5，总像素最高 250 万，避免大屏与高像素倍率叠加开销。
- 静止、暂停和收尾完成后停止 requestAnimationFrame；交互、尺寸变化与承重脉冲按需唤醒。
- 同一时刻最多挂起一个动画回调，避免步骤切换再次分叉动画循环。

## 回归验证

算法与所有修复案例、前后单步、暂停续播、重置/换场景、倍速、输入拒绝保持验证；新增检查覆盖小图缓存复用、主舞台无实时模糊/阴影、像素预算、实际渲染器收尾停止、静止暂停停止绘制、动画回调不分叉。
