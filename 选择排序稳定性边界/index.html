选择排序代码逐行追踪 (C Implementation)

内层循环零交换，仅更新索引
01void SelectSort(int A[], int n) {
02 for (int i = 0; i < n - 1; i++) {
03 int minIndex = i; // 只记索引，不搬元素
04 for (int j = i + 1; j < n; j++)
05 if (A[j] < A[minIndex]) // 严格小于
06 minIndex = j; // 指针平移，代价 O(1)
07 if (minIndex != i) // 自交换规避
08 swap(A[i], A[minIndex]); // 趟末唯一交换
09 } // 该位固化为有序区，边界右移
10}

408 考点深度精炼 (Selection Sort)

轻量化移动 · 不稳定性成因
◆ 轻量化移动机制：只记索引，趟末单次交换
内层扫描过程中零交换、零搬移，仅做“比较 → 刷新 minIndex 指针”，每趟至多在末尾触发 1 次 swap。n 趟总交换次数 ≤ n−1，本例严格为 3 次。
◆ 比较次数恒定：n(n−1)/2
无论序列是否有序，内层 j 都必须扫到底，比较次数恒为 6 = 4×3/2 次 —— 这也是选择排序对“已有序输入”无法加速的原因，时间复杂度始终 O(n²)。
◆ 不稳定性根因：远距离跨越交换
首趟把 5_A 从下标 0 一步换到下标 3，跨过了下标 2 的 5_B，原相对次序 5_A…5_B 突变为 5_B…5_A —— 这正是“选择排序是不稳定排序”的经典边界场景。
◆ 自交换规避与时空复杂度
当某趟扫完发现 minIndex == i（如末趟单元素）时直接跳过 swap，避免无意义自交换；整体原地排序，空间复杂度 O(1)。
